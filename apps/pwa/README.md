# MyMind PWA

Параллельное приложение Next.js. Android/iOS и desktop остаются в репозитории. Удалённой базы данных нет: SQLite WASM выполняет запросы в браузере, IndexedDB хранит снимки SQLite и бинарные вложения на устройстве. Next.js раздаёт приложение и, при явном включении, передаёт зашифрованные сообщения LAN-протокола существующему desktop.

## Запуск

Из корня репозитория, Node.js >= 22.13:

```powershell
npm.cmd run dev:pwa
# Production, включая офлайн-кэш:
npm.cmd run build:pwa
npm.cmd run start:pwa
```

Адрес: `http://localhost:3000`. В dev service worker отключён. Для первого офлайн-запуска откройте production-приложение с сетью и дождитесь «Готово к офлайн». После этого приложение запускается из браузерного кэша без сервера. YouTube, внешние изображения и ссылки требуют сети.

## Данные и перенос

База `mymind-pwa-v1` принадлежит текущему origin: схема, домен и порт имеют значение. Очистка данных сайта удаляет библиотеку; смена адреса не переносит её автоматически. В настройках есть запрос постоянного хранения и резервное копирование.

Используются общие миграции мобильной схемы 1–9 и репозитории `@mymind/persistence`. SQL-порт синхронный; запись снимков в IndexedDB асинхронная. Нижний индикатор подтверждает завершённую запись. Ошибка записи блокирует дальнейшие SQL-изменения до успешного повтора. Web Locks допускает одного писателя: вторая вкладка просит закрыть первую. При обновлении service worker меняется только кэш приложения, IndexedDB сохраняется. Обновление ждёт закрытия всех окон.

Вложения сохраняются до включения в документ, удаляются после подтверждённого сохранения SQLite. IndexedDB хранит байты и MIME-тип файлов: это также работает в реализациях WebKit, отклоняющих Blob/File. Прежние записи Blob читаются без отдельного переноса. В SQLite остаются переносимые ссылки; Blob URL восстанавливаются при запуске и после синхронизации. Секрет профиля зашифрован AES-GCM неэкспортируемым WebCrypto-ключом в IndexedDB. Мастер-пароль сейфа использует прежнюю схему шифрования.

### Из Android/iOS

В текущем мобильном приложении экспортируйте `.mymindbackup`, затем выберите его в настройках PWA. Прямого доступа браузера к приватным данным установленного приложения нет. Исходное приложение и данные сохраняются.

Контейнер `MYMIND01`, версия схемы, пути, SHA-256, целостность SQLite и внешние ключи проверяются до замены. Дополнительно проверяются документы заметок и материалов, наличие и размер файлов, на которые ссылается библиотека. База и вложения заменяются одной транзакцией IndexedDB; ошибка сохраняет прежнюю библиотеку PWA. Контрольные суммы вложений считаются потоково. Действуют общие пределы формата: до 4 ГБ содержимого, SQLite до 512 МБ, манифест до 4 МБ. Практический размер ограничен памятью и квотой устройства: SQLite остаётся в памяти. Системный секрет LAN-профиля в резервную копию не входит; после импорта введите учётные данные профиля заново.

### Из desktop

Полностью закройте desktop MyMind. В настройках PWA выберите «Перенести desktop-библиотеку» и папку MyMind, содержащую `data/mymind.sqlite` и `Attachments`. Импорт копирует все совместимые таблицы, оформление и вложения, проверяет структуру, внешние ключи, ссылки и размеры файлов. Непустой WAL, недостающий файл или несовместимая схема останавливают перенос без замены текущей PWA-базы. Исходные файлы не изменяются. Для старой desktop-схемы сначала обновите desktop. Выбор папки удобнее выполнять в браузере компьютера; затем можно перенести `.mymindbackup` на телефон. Desktop backup-контейнер не следует выбирать вместо папки библиотеки.

## LAN и HTTPS на телефоне

```powershell
npm.cmd run start:pwa:lan
```

Этот запуск включает `MYMIND_LAN_SYNC_ENABLED=1` только для локального процесса. В desktop также включите LAN-синхронизацию. Профиль на обоих устройствах должен иметь одинаковые логин и пароль. Сначала доступны обнаружение и предварительный просмотр, затем обмен выбранными модулями и вложениями. Протокол сохраняет исходные challenge/proof, AES-GCM, ревизии и разрешение конфликтов.

Relay принимает только известные endpoints протокола, порты 49632–49636, loopback или частные IPv4 своей /24 сети. Произвольные URL, DNS-имена, перенаправления и запросы с чужого origin отклоняются. LAN API исключён из офлайн-кэша. На сервере нет пользовательской SQLite или постоянного хранилища вложений. Для обмена локальный сервис и desktop должны работать, для обычной офлайн-работы они не нужны.

На телефоне требуется **HTTPS с сертификатом, которому устройство доверяет**. HTTP по IP компьютера не даёт полноценный PWA secure context. Локальный запуск умеет принимать существующий сертификат:

```powershell
$env:MYMIND_HTTPS_CERT = 'C:\certificates\mymind.pem'
$env:MYMIND_HTTPS_KEY = 'C:\certificates\mymind-key.pem'
# Необязательно: другой порт
$env:MYMIND_PWA_PORT = '3000'
npm.cmd run start:pwa:lan
```

Сертификат должен включать адрес, который открывается на телефоне. Скрипт не устанавливает корневые сертификаты и не отключает TLS-проверку. Альтернатива — настроенный HTTPS reverse proxy к локальному Next.js. Сохраняйте один адрес для существующей библиотеки.

На iPhone: Safari → «Поделиться» → «На экран Домой». На Android: установка через меню Chrome либо кнопку настроек PWA.

## Напоминания и системные отличия

При открытом PWA календарь и привычки создают системные уведомления после разрешения пользователя. Запись о доставке сохраняется до показа; после сбоя уведомление остаётся непрочитанным внутри приложения. Пропущенные события подхватываются при открытии, без повторной доставки; максимальное окно восстановления — 30 дней.

Полностью закрытый PWA не выполняет постоянные локальные таймеры. По выбору пользователя напоминания остаются только на устройстве, ограничения фоновой работы приняты; внешний push-сервис не используется. Экспорт `.ics` передаёт предстоящие напоминания на 30 дней в системный календарь для офлайн-сигналов; после изменения расписания файл нужно экспортировать повторно. Это явный обходной путь, а не автоматические фоновые уведомления PWA.

Запись голоса использует MediaRecorder и разрешение микрофона. Открытие файла использует браузерный просмотр/скачивание. PDF использует системный диалог печати: браузер не сообщает, сохранил пользователь файл или отменил. Квоты хранения и поддержка форматов аудио зависят от браузера.

## Проверки

```powershell
npm.cmd run check:pwa
# Один раз установить тестовый WebKit; Chrome должен быть установлен:
node node_modules/playwright/cli.js install webkit
# После production-сборки:
npm.cmd run test:e2e:pwa
npm.cmd run typecheck:web --workspace=mymind-next
npm.cmd run typecheck:mobile
```

139 тестов проверяют общую логику и репозитории на браузерной SQLite, миграции, IndexedDB, сбои записи, backup, атомарный перенос desktop, DSL, доски, тренировки, криптографию профиля, реальные TCP-сессии с desktop LAN-сервером, чанки вложений, напоминания и service worker. Тестовый адаптер `better-sqlite3` использует sql.js и не перестраивает нативный модуль Electron.

18 сценариев Playwright проверяют изменение и удаление данных, перезапуск приложения, сейф, вложения, резервные копии, режим кода «Учёбы», доски, офлайн-кэш всех разделов и блокировку второго писателя. Конфигурации: Chrome 1280×900, Chrome 390×844 с сенсорным вводом, WebKit 390×844 — всего 54 запуска. Для записи голоса Chrome получает тестовый аудиопоток через настоящий MediaRecorder; в WebKit тот же сценарий проверяет изображения, сохранение и backup/restore, без недоступного тестового микрофона. WebKit на Windows не заменяет Safari на iPhone.

Артефакты находятся в `.data/pwa-browser-results`, пользовательский профиль браузера не используется. Локальный HTTPS дополнительно проверен с доверенным только тестовым запросом CA: приложение, WASM, LAN и отказ неавторизованного запроса. Подробное соответствие исходным разделам и границы проверок описаны в [PARITY.md](./PARITY.md).

Физические iPhone/Android, установка, разрешения микрофона/уведомлений, большие реальные библиотеки и LAN между реальными устройствами требуют отдельной приёмки. Прошедшая сборка и автоматические тесты не означают идеальное соответствие на каждом устройстве. Нативные версии сохраняются до этой приёмки.
